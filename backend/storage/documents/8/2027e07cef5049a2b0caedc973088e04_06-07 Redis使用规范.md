# 星云智联科技有限公司 Redis 使用规范

| 版本 | 适用 |
| --- | --- |
| V1.0 | 研发中心 · 后端开发 |

---

## 一、数据类型与使用场景

| 类型 | 适用场景 |
| --- | --- |
| String | 分布式锁、计数器、缓存单值 |
| Hash | 对象字段缓存、配置项 |
| List | 消息队列（简单）、最近列表 |
| Set | 去重、集合运算 |
| ZSet | 排行榜、时间序列表 |

- 根据数据特性选型，避免误用（如大 Key 塞 List 全程遍历）。

---

## 二、Key 命名规范

- 格式：`业务:模块:标识[:字段]`（冒号分隔）。
- Key 语义清晰，示例：`order:lock:1001`、`user:token:9527`。
- 控制 Key 长度与体量，避免超大 Key（大 Key 提前拆分）。

---

## 三、过期策略

- 缓存务必设置 **TTL（过期时间）**，防止缓存永久占用。
- 热点数据根据业务选择合适的过期时间，避免同时失效雪崩。

---

## 四、缓存穿透 / 击穿 / 雪崩

| 问题 | 描述 | 应对 |
| --- | --- | --- |
| 穿透 | 查询不存在数据反复压库 | 缓存空值 + 布隆过滤器 |
| 击穿 | 热点 Key 失效瞬间打库 | 互斥/分布式锁重建缓存 |
| 雪崩 | 大量 Key 同时过期 | 过期时间加随机抖动 |

---

## 五、分布式锁使用

- 使用 Redisson/Redis 官方方案的分布式锁。
- 必须设置过期时间，防止死锁。
- 释放时校验持有者（唯一标识），避免误删他人锁。
- 保持锁粒度与业务范围一致，锁内不放耗时操作。

---

## 六、序列化规范

- 统一序列化方式（如 JSON/redis-template 配置一致）。
- 值存储结构化数据时明确类型，避免反序列化歧义。

---

## 七、其他注意

- 合理规划实例与内存，监控 `used_memory`、`miss` 率。
- 敏感信息不入 Redis 明文（需加密）。

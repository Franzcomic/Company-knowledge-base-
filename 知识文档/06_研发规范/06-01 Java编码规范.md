## 一、命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 包名 | 全小写，域分隔 | `com.nebula.oa.service` |
| 类/接口 | 大驼峰（PascalCase） | `UserService`、`OrderServiceImpl` |
| 方法/变量 | 小驼峰（camelCase） | `getUserName()`、`totalCount` |
| 常量 | 全大写，下划线分隔 | `MAX_RETRY_COUNT` |
| 枚举 | 类型大驼峰，值全大写 | `StatusEnum.SUCCESS` |
| 布尔变量 | 用 is/has/can 前缀 | `isActive` |

### 命名原则
- 语义清晰、见名知义，避免拼音、缩写（约定俗成除外）。
- Controller 以 `Controller` 结尾，Service 以 `Service/ServiceImpl` 结尾，DTO/VO 明确后缀。

## 二、注释规范

- 类、方法、复杂逻辑须写**Javadoc 注释**，说明用途、参数、返回与异常。
- 关键业务分支写行内注释说明意图。
- 注释应描述「为什么」而非重复代码本身。
- 禁止留下无用、过期或误导性注释。

```java
/**
 * 根据用户ID查询用户信息
 *
 * @param userId 用户ID，不能为空
 * @return 用户信息，不存在时返回 null
 */
public UserVO getUserById(Long userId) { ... }
```

---

## 三、异常规范

- 业务异常使用统一的**业务异常（BusinessException）**抛出。
- 捕获异常应处理或重新抛出，禁止空 catch 吞掉异常。
- 捕获特定异常而非笼统 Exception。
- 返回值与异常语义一致，避免用返回值掩盖失败。

## 四、日志规范

### 4.1 日志框架
- 统一使用 SLF4J + Logback，通过 `LoggerFactory.getLogger(xxx.class)` 获取。

### 4.2 日志级别
| 级别 | 使用时机 |
| --- | --- |
| TRACE/DEBUG | 调试、开发期细节 |
| INFO | 关键业务流程节点 |
| WARN | 可恢复的异常/潜在问题 |
| ERROR | 未处理的错误、异常 |

### 4.3 日志要求
- 使用占位符：`log.info("userId={}", id);` 避免字符串拼接。
- **敏感信息脱敏**：密码、手机号、身份证等不得明文打日志。
- 日志输出包含足够定位信息（方法名、关键入参）。

## 五、代码其他要求

- 遵循约定优于配置，控制单个方法/类规模，保持高内聚、低耦合。
- 提交前自测，减少重复代码，主动消除编译告警。

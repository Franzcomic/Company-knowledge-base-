# 基于 RAG 的企业内部知识库客服系统——后端实施方案

> 本文档是《项目实施计划.md》（`d:\Corpedia\plan\项目实施计划.md`）的后端专项落地细化，与《前端实施计划.md》配套。按 **阶段 1→5** 组织，覆盖模块 ①~⑧，全量 P0→P2。

> 技术主线：**Spring Boot 4.x + Spring AI 2.0 + Java 21 + MyBatis-Plus + MySQL 8 + Milvus + Ollama（gemma-4-e4b LLM / bge-m3 Embedding）**。

## 一、Summary（本方案要解决什么）

- 目标：把《项目实施计划.md》中 8 个模块的后端/RAG/AI 任务，落成**可直接照着写代码**的、按阶段推进的后端实施清单；与前端已锁定的接口契约严格对齐。
- 现状：`d:\Corpedia` 下已有 `frontend` 骨架（登录可用，Chat / Kb 为占位），**后端尚未创建**；知识文档（9 类 60+ 篇 md）与测试集已就绪。
- 结论：以 Maven 多模块单工程 `backend/` 起步，按阶段 1→5 实现；数据库用 MyBatis-Plus；RAG 编排用 Spring AI 2.0。

## 三、后端总览与分层

```
Spring Boot 4 后端  backend/
│  Controller 层    REST + 统一返回 {code,msg,data} + 全局异常
│  Service 层       业务编排（文档管道 / RAG 链路 / 会话 / 统计）
│  Repository 层     MyBatis-Plus Mapper（MySQL 业务元数据）
│  AI 层            Spring AI 2.0：EmbeddingModel / VectorStore(Milvus) / ChatModel(Ollama)
│  Data 层          MySQL 8（业务）  ·  Milvus（向量）  ·  Redis（缓存,可选）
└─ 基础设施         Spring Security + JWT · Jackson · Tika · @Retryable
```

**分层职责**
- **Controller**：仅做参数接收 + 鉴权注解 + 返回统一结构，不含业务。
- **Service**：业务编排。文档入库走管道（异步任务），问答走 RAG 编排。
- **Mapper（MyBatis-Plus）**：10 张业务表的 CRUD。
- **AI 层**：`EmbeddingModel`、`VectorStore.similaritySearch`、`ChatClient`。

### 4.3 统一返回与异常
- `Result<T>{ code, msg, data }`，`ResultCode` 枚举（200 成功、401 未授权、400 参数、404、500）。

## 五、数据库设计（MySQL 8，MyBatis-Plus）

共 10 张表，见《项目实施计划.md》§5。MyBatis-Plus 约定：实体名+Mapper；主键 `ASSIGN_ID`（雪花）或自增，建议 `id` 自增 BIGINT；创建/更新时间用 `created_at/updated_at`。

| 表 | 关键字段 | 备注 |
|---|---|---|
| `user` | username UNIQUE, password_hash, real_name, email, phone, department_id, role_id, status | 密码 BCrypt |
| `department` | name, parent_id, description | P1 |
| `role` | code(EMPLOYEE/DEPT_ADMIN/SYS_ADMIN), name | 数据字典 |
| `permission` | role_id, resource, access_level(PUBLIC/DEPT/CONFIDENTIAL) | P1 |
| `knowledge_base` | name, department_id(可空=全司), description, permission_level, created_by | |
| `document` | kb_id, filename, file_path, file_type, size, status(PARSING/READY/FAILED), chunk_count, permission_level, uploaded_by | 状态驱动入库 |
| `conversation` | user_id, title, department_id, status | |
| `message` | conversation_id, role(USER/ASSISTANT), content, sources(JSON), similarity, answered(bool) | sources 存 JSON |
| `feedback` | message_id, user_id, rating(UP/DOWN), reason | P1 |
| `qa_statistics` | stat_date, qa_total, answered_count, not_answered_count, hit_rate, avg_response_ms, category_distribution(JSON) | P2 |

DDL 落位：`backend/src/main/resources/db/schema.sql`（含索引：document(kb_id)、message(conversation_id)、conversation(user_id)）。

## 六、接口契约对齐（前端已固定，后端必须匹配）

前端 `request.ts`/`api/auth.ts`/`stores/user.ts` 已锁定的约定：

- 路径前缀：前端 `baseURL=/api`，调用 `/auth/login` → 后端实际 `**/api/auth/login**`。后端用 `server.servlet.context-path=/api` 或各 Controller `@RequestMapping("/api/...")` 统一。
- 返回：`{code,msg,data}`；`code=200` 成功、`code=401` 未授权。
- 鉴权：请求头 `Authorization: Bearer <token>`。
- 已固定接口：
  - `POST /auth/login`，body `{username,password}` → data `{token, user}`
  - `POST /auth/logout` → data `null`
  - `GET /auth/me` → data `UserInfo`
- `UserInfo` 字段（后端响应对齐）：`id, username, realName, departmentId, roleId, roleCode, roleName, email, phone`。
- `LoginResult`：`token, user`。

## 七、阶段拆解（对应《项目实施计划.md》阶段 1~5）

### 阶段 1 · 环境与工程搭建 + 登录认证（模块① P0）

**目标**：前后端、MySQL、Milvus、Ollama 均可本地连通；能登录；AI 组件可调用。

**后端任务**
- [ ] 初始化 `backend/` Maven 工程，验证 Spring Boot 4 + MyBatis-Plus + Spring AI 2.0 依赖可解析、启动成功。
- [ ] `application.yml`：数据源（MySQL）、Ollama base-url(11434)、Milvus(19530)、Spring AI 组件映射（见 §九 RAG 参数）、文件上传大小（与前端 `.env VITE_UPLOAD_MAX_MB=10` 一致，设 `spring.servlet.multipart`）。
- [ ] Docker Compose：`compose.yaml` 拉起 MySQL 8、Milvus(standalone: etcd+minio+milvus)、可选 Redis。
- [ ] `schema.sql` 首次执行建 10 表 + 种子数据（admin/正常用户、role: EMPLOYEE/DEPT_ADMIN/SYS_ADMIN）。
- [ ] Security + JWT：`JwtAuthFilter`（解析 · 校验 · 注入 `UserContext`）、`SecurityConfig`（放行 `/auth/login`、其余鉴权）、`LoginService`（BCrypt 比对 → 签发 token → 返回 `LoginResult`）。
- [ ] 接口：`POST /auth/login`、`POST /auth/logout`、`GET /auth/me`。
- [ ] Spring AI 探针：`ChatClient`（本地回一句）、`EmbeddingModel`（输出 1024 维）、Milvus 连通 Bean。

**验收**：前端 `LoginView` 能登录；`/auth/me` 返回完整 `UserInfo`；一个探针接口能返回 LLM 回答与向量维数；Milvus 无连接异常。

---

### 阶段 2 · 文档入库管道（模块② P0 + 模块③）

**目标**：`知识文档\` 文档可上传、解析、清洗、分块、Embedding、写 Milvus，状态可见。

**后端任务**
- [ ] 知识库：`KbController` 增删改查（`GET/POST/PUT/DELETE /api/kb`）。
- [ ] 文档：`DocumentController`：
  - `POST /api/kb/{kbId}/documents` multipart 上传 → 落盘 `backend/data/uploads/` → 插 `document(status=PARSING)` → 触发异步管道。
  - `GET /api/kb/{kbId}/documents` 文档列表（含 status）。
  - `GET /api/documents/{id}` 详情（含 chunk_count）。
  - `DELETE /api/documents/{id}` 删记录 + 级联清 Milvus。
- [ ] 文档处理管道（`ai/` 内，异步 + Spring Framework 7 `@Retryable`）：
  1. 解析：Tika 抽取 md/pdf/docx/txt 文本。
  2. 清洗：去页眉脚/目录/空行/乱码/重复段。
  3. 分块：`ChunkSize=500/Overlap=100`（`TokenTextSplitter` 或自定）。
  4. Metadata：`document_id/title/department/category/permission_level/source`。
  5. Embedding：`EmbeddingModel`（bge-m3, 1024）。
  6. 写 Milvus：`VectorStore.add()`；成功 → `document.status=READY, chunk_count=N`；失败 → `FAILED`。
- [ ] `POST /api/rag/process/{documentId}` 触发/重试入库。

**验收**：员工手册、财务报销各 1 篇成功入库；Milvus 可查询到 chunk；文档状态流 PARISNG→READY/FAILED 正确。

---

### 阶段 3 · RAG 问答主链路（模块④ P0 + ⑤ + ⑥ + ⑦）

**目标**：员工提问 → 检索 → 生成带来源答案 → 会话与历史落库。

**后端任务**
- [ ] 检索（`RagService.retrieve`）：`EmbeddingModel.embed(query)` → `MilvusVectorStore.similaritySearch(SearchRequest, TopK)` → 返回片段+相似度。
- [ ] 生成（`RagService.chat`，复用 `/api/rag/chat`）：拼接 System Prompt + Context + question → `ChatClient` → 解析结构化输出（答案+来源）；低分/未命中使用兜底文案。
- [ ] 会话：`ConversationController`：`GET/POST/DELETE /api/conversations`；`GET /api/conversations/{id}/messages`。
- [ ] 消息：`POST /api/messages` 提问 → 检索+生成 → 持久化 user 与 assistant 两条 message（含 sources JSON、similarity、answered）→ 返回答案+来源。
- [ ] 历史：会话侧栏列表、历史消息读取（模块⑦ 复用同表）。

**验收**：用测试集 precision 类（如年假天数、报销标准）回答正确并带来源；来源可点击；多轮会话与历史可续聊；`non_exist` 走兜底文案。

---

### 阶段 4 · 权限与检索增强（模块① P1 + ② P1 + ④ P1 + ⑥ P1）

**目标**：权限隔离 + 检索质量提升；财务只能答财务内容，`non_exist` 正确拒答。

**后端任务**
- [ ] 部门/角色：`DepartmentController`、`RoleController` CRUD（`/api/departments`、`/api/roles`）。
- [ ] 用户管理：`GET/PUT /api/users[/{id}]`（列用户、改角色/部门/启停用）。
- [ ] 权限判定：`PermissionService` 做越权校验；管理器/资源按 role 控制。
- [ ] 文档 P1：`POST /api/documents/{id}/reprocess` 重向量化；`GET /api/documents/{id}/chunks`；`PUT /api/documents/{id}/permission`。
- [ ] 检索增强（`RagRetrieveService`）：
  - **Metadata Filter**：检索强制注入 `department == user.department && permission_level <= user.level` 的 Milvus 标量过滤表达式。
  - **相似度阈值**：低于阈值拒答，返回兜底。
  - **Query Rewrite**：口语→规范问句（可选，P1）。
  - **Rerank**：Top10→Top3（bge-reranker 或按相似度排序，P1）。
- [ ] 评价：`POST /api/messages/{id}/feedback`（赞/踩+原因）。

**验收**：财务角色检索不到非财务内容（越权/拒答用例通过）；`non_exist` 正确拒答；评价落库生效。

### 阶段 5 · 统计与完善（模块⑧ P2）

**目标**：管理员统计看板数据。

**后端任务**

**验收**：统计接口与前端看板数据一致，与草案目标逐项核对。

## 九、RAG 关键参数（集中配置，`application.yml`）

```yaml
spring:
  servlet.multipart: { max-file-size: 10MB, max-request-size: 10MB }
  ai:
    model: { chat: ollama, embedding: ollama }
    ollama:
      base-url: http://localhost:11434
      chat.options:  { model: google/gemma-4-e4b, temperature: 0.2 }
      embedding.options: { model: bge-m3 }
    vectorstore.milvus:
      client: { host: localhost, port: 19530, databaseName: default }
      initialize-schema: true
      embedding-dimension: 1024
rag:
  chunk-size: 500
  chunk-overlap: 100
  top-k: 10
  rerank-top: 3
  similarity-threshold: 0.6     # 低于此值拒答
  collection: knowledge_chunks # 度量 COSINE
```

Prompt 模板与兜底文案沿用《项目实施计划.md》§4.5。

## 十一、风险与注意事项（后端侧新增）

| 风险 | 应对 |
|---|---|
| Spring Boot 4 / Spring AI 2.0 / MyBatis-Plus 兼容 | 阶段 1 先最小工程冒烟；MyBatis-Plus 若无 boot4 starter，回退 Spring JdbcTemplate 或暂用标准 starter；以官方文档核对 artifact 前缀 |
| Ollama 模型 tag 拉取 | 以实际可拉取 tag 为准，`ollama list` 核对 gemma-4-e4b / bge-m3 维度 1024 |
| Tika 解析差异 | 清洗强化；失败标 FAILED 提示重传 |
| 权限 Filter 遗漏 | 检索强制注入权限表达式，测试越权/拒答 |
| LLM 幻觉 | 严格 Prompt + 相似度阈值 + 兜底文案 |
| 异步入库状态一致性 | 管道幂等（按 document status 流转），`@Retryable` + 失败落库 |

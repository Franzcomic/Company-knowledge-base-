# 基于 RAG 的企业内部知识库客服系统 · 项目启动手册

> 配套文档：《项目实施计划.md》《后端实施方案.md》《前端实施计划.md》
> 适用环境：Windows 开发机（实测 JDK 25 + Maven 3.9.16 + Node 22 + MySQL 8.0.44 + Milvus v3.0.1 容器 + LM Studio）
> 说明：本项目启动需按顺序拉起 **MySQL → Milvus → LM Studio → 后端 → 前端** 五个部分，缺一不可。

---

## 1. 系统架构总览

```
┌──────────────┐   /api 代理    ┌───────────────────────┐
│  前端 (Vue3)  │ ─────────────► │  后端 (Spring Boot 4) │
│  Vite :5173  │                │  Tomcat :8080         │
└──────────────┘                └──────┬───────┬────────┘
                                       │       │
                         MySQL :3306   │       │   Milvus :19530
                         (业务数据)     │       │   (向量库: knowledge_chunks)
                                       │       │
                        ┌──────────────┴───────┴──────────┐
                        │   LM Studio (OpenAI 兼容) :1234  │
                        │   chat: google/gemma-4-e4b       │
                        │   embedding: text-embedding-bge-m3│
                        └──────────────────────────────────┘
```

### 端口矩阵

| 端口 | 组件 | 用途 |
|---|---|---|
| 3306 | MySQL | 业务数据库 `corpedia` |
| 19530 | Milvus | 向量库 gRPC 端口 |
| 9091 | Milvus | 健康检查 `/healthz` |
| 2379 | etcd | Milvus 元数据（容器内） |
| 9000 / 9001 | MinIO | Milvus 存储 / 控制台（容器内） |
| 1234 | LM Studio | 本地 OpenAI 兼容 API |
| 8080 | 后端 | Spring Boot（接口统一前缀 `/api`） |
| 5173 | 前端 | Vite 开发服务器 |

## 3. 启动步骤（严格按顺序）

### 3.1 MySQL（若未运行）

```powershell
# 启动 Windows 服务（管理员 PowerShell）
net start MySQL80
```

- 账号：`root` / `123456`
- 数据库：`corpedia`（utf8mb4）——**无需手工建表**，后端启动时 `spring.sql.init` 自动执行 `db/schema.sql` 创建 10 张表，`DataSeeder` 幂等写入种子数据，`DatabaseMigrator` 自动补齐 `message.response_ms` 列。
- JDBC 连接串已含 `allowPublicKeyRetrieval=true`（MySQL `root` 为 `caching_sha2_password` 认证，缺该参数会报 "Public Key Retrieval is not allowed"，见 §7 排查）。
- 若数据库不存在需先建库：

```sql
CREATE DATABASE IF NOT EXISTS corpedia DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

### 3.2 Milvus（若容器未运行）

```powershell
# 在 backend 目录执行（compose.yaml 定义 etcd + minio + milvus 三个服务）
cd D:\Corpedia\backend
docker compose up -d
```

验证：

```powershell
docker ps        # 三个容器均应为 Up (healthy): milvus-standalone / milvus-etcd / milvus-minio
curl http://localhost:9091/healthz   # 返回 OK
```

> 数据持久化在 `backend\volumes\`（etcd / minio / milvus），删除容器不影响数据。

### 3.3 LM Studio（模型服务，端口 1234）

1. 打开 LM Studio 桌面应用。
2. 确认已加载（或加载）两个模型：
   - 聊天模型：`google/gemma-4-e4b`（与 `application.yml` 中 `ai.openai.chat.model` 一致）
   - Embedding 模型：`text-embedding-bge-m3`（1024 维）
3. 启动本地服务器（或点击 UI 上的 "Start Server"）：

```powershell
lms server start
```

验证：

```powershell
# 应返回包含上述两个模型 id 的列表
curl http://localhost:1234/v1/models
```

### 3.4 后端（Spring Boot，端口 8080）

```powershell
cd D:\Corpedia\backend
mvn spring-boot:run
```

> 注意：
> - **必须在 `D:\Corpedia\backend` 目录下启动**（`corpedia.storage.path=./storage/documents` 为相对路径，文档文件落盘于此）。
> - 启动成功标志：日志出现 `Started CorpediaApplication`，Tomcat 监听 8080；随后日志输出 `[DataSeeder] 种子数据就绪`。
> - 生产式启动（可选）：`mvn -DskipTests package` 后 `java -jar target\corpedia-backend-0.0.1-SNAPSHOT.jar`。

### 3.5 前端（Vue 3 + Vite，端口 5173）

```powershell
cd D:\Corpedia\frontend
npm install        # 仅首次或依赖变更时
npm run dev
```

- 访问：`http://localhost:5173`
- Vite 已配置 `/api` 代理到 `http://localhost:8080`（见 `vite.config.ts` 与 `.env`），浏览器端无跨域问题。
- 若需直连其他后端地址，修改 `frontend\.env` 的 `VITE_API_PROXY` 后重启 dev server。
- 生产构建（可选）：`npm run build`，产物在 `frontend\dist\`，可用 `npm run preview` 预览。

## 6. 停止与重启

### 停止（逆序）

```powershell
# 1) 前端: 按 Ctrl+C 停掉 npm run dev
# 2) 后端: 按 Ctrl+C 停掉 mvn spring-boot:run
# 3) LM Studio: lms server stop（或关闭桌面应用）
# 4) Milvus（可选）:
cd D:\Corpedia\backend
docker compose down
# 5) MySQL（可选）: net stop MySQL80
```

### 日常重启

只需重启后端/前端即可，MySQL、Milvus、LM Studio 常驻不关：

```powershell
cd D:\Corpedia\backend && mvn spring-boot:run        # 新开终端
cd D:\Corpedia\frontend && npm run dev               # 新开终端
```

## 7. 常见问题排查

| 现象 | 排查与解决 |
|---|---|
| 后端启动报连不上 Milvus | `docker ps` 看三个容器是否 healthy；`curl http://localhost:9091/healthz`；否则 `docker compose up -d` |
| 后端启动报连不上 LM Studio / 模型不存在 | `curl http://localhost:1234/v1/models` 核对模型 id 与 `application.yml` 的 `ai.openai.chat.model` / `embedding.model` 是否一致；LM Studio 加载后需重启 server |
| 后端启动报 MySQL 连接失败 | `net start MySQL80`；确认 `corpedia` 库存在、`application.yml` 账号密码正确 |
| 后端启动报 `Public Key Retrieval is not allowed` | MySQL `root` 使用 `caching_sha2_password` 认证，非 TLS 连接需在 JDBC URL 加 `&allowPublicKeyRetrieval=true`（`application.yml` 已配置；新 JVM/MySQL 重启后缓存失效会触发该问题） |
| 端口 8080 被占用 | `netstat -ano | findstr :8080` 找到 PID，结束旧进程或改 `application.yml` 端口 |
| 前端访问接口 404 / 跨域 | 确认后端已启动且 Vite 代理生效（`frontend\.env` 的 `VITE_API_PROXY`）；刷新页面重试 |
| 上传文档后状态一直是 PARSING | 后端日志看是否有解析异常；确认 LM Studio embedding 模型正常（RAG 链路依赖） |
| PowerShell 调试脚本里中文乱码 | 仅客户端显示问题（PS 5.1 ANSI 解析 + `Invoke-RestMethod` Latin-1 解码），后端返回内容本身是正确 UTF-8；脚本改为从 UTF-8 配置文件读取请求体 |
| 相似度命中偏低 / 误拒答 | 阈值 `corpedia.rag.similarity-threshold` 当前 0.5（bge-m3 实测校准值），非知识库问题与相关知识区分明显，勿随意调高 |
